### 2.2 Product image-order schema decision

The owner selected the database-enforced uniqueness option on 2026-10-25. The isolated clean-reset target DDL replaces non-unique `ix_product_images_product_order` with `UNIQUE (product_id, sort_order)` named `uq_product_images_product_order`; the Data Dictionary references that same index and the ERD notes the physical composite invariant. P1.3 requires the application to serialize/lock gallery mutations and maintain contiguous `0..n-1` order plus the sole primary image at position zero. The unique index prevents duplicates but cannot enforce contiguity. Before applying this index to any populated database, an approved migration must detect and repair duplicate positions, gaps and primary-image mismatches. No live database or active Flyway chain was changed.

### 2.3 Order seed-permission decision

The owner selected `ORDER_EDIT` to replace the target-seed permissions `ORDER_PROCESS`, `ORDER_FULFILLMENT` and `ORDER_EXCEPTION`. The normative target manifest and isolated clean-reset seed now contain 13 permissions. The P1.7 transition/action matrix remains authoritative for exactly which Order operations are allowed; payment/collection and after-sales remain separate under `ORDER_PAYMENT` and `ORDER_AFTER_SALES`. This does not grant the permissions to ADMIN or any other role implicitly. Legacy runtime seed code/tests may still mention the retired permission constants and are not target runtime acceptance.
