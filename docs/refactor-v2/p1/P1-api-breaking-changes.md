# P1 — Target API/DTO/Frontend Breaking-Change Map

**Status: INVENTORY — IMPLEMENTATION NOT COMPLETE.** This file compares the current runtime implementation with the owner-approved target. Source observations are migration evidence, not alternative target requirements.

The target clean-reset schema remains isolated from the active legacy Flyway migration chain. P2/P3 must update backend and frontend to the target contract as a coherent cross-layer change; this file does not authorize keeping compatibility fields/routes that contradict the target.

| Domain | Current implementation evidence | Approved target contract | Required implementation/acceptance |
|---|---|---|---|
| Account identity | Current Account entity has a legacy account ID mapping, globally unique phone and no mapped soft-delete field. | ACCOUNTS.id; soft delete; active-phone-only uniqueness and phone reuse after soft delete. | Remap Entity/auth/repositories/DTO; verify active duplicate rejection and reuse on MySQL. |
